Monolith

Team project, Unity and C#

A dungeon-crawling action RPG built by a student team from vertical slice through alpha and beta. I owned most of the systems that decide what a run feels like: what spawns, what drops, how hard it gets and how fast you unlock things.

I ran the balance pass during beta and kept the team's technical and game design docs current for every system I touched.

UnityC#Procedural generationSystems design

Systems I built

  • Dungeon generation. Room layout with snapping folded into layout validation so rooms can never overlap, plus a trap and room lockdown pass.
  • Difficulty scaling. Level-scaled dungeon difficulty anchored to a target player level, with chapter-based progression as real game data.
  • Unlock pacing. A chapter unlock schedule with an early XP curve and a skill point balance reconciled from level.
  • Enemies and elites. Enemy aggro rules and a roster of elite affixes that can be switched on and off for tuning.
  • Loot and Divine items. Item generation, equipment stat wiring and a set of unique items with their own gameplay hooks.
  • Runes. Rune stats and flags, and the rune selection panel UI.

Stick Wars

Unity 6.3, PC and PlayStation 5

A four-player local brawler in the spirit of Stick Fight, where every fighter is a physics-driven ragdoll. Rounds run first to five points across rotating arenas.

UnityC#PhysicsLocal multiplayer

Systems I built

  • Active ragdolls. Stick figures with muscle-driven joints, procedural animation and foot IK.
  • Movement. Run, jump, wall bounce, fast fall and crouch.
  • Combat. Punches and an air kick sharing one strike system, with health, headshots and round flow.
  • Weapons. Twelve data-driven weapons, from pistols and shotguns to swords and spears, with pickup, throw and drop.
  • Arenas. Five rotating arenas with moving, crumbling and lethal hazards.

C++ Loot Generator and Mass Damage Resolver

Solo, C++20, Visual Studio

Two ARPG systems in pure C++, written to show how memory layout and ownership affect real game code.

  • Loot generator rebuilt from Monolith's real loot tables and item modifier data
  • A 10,000-kill boss test keeps every rarity within 0.31 points of its expected drop rate, with no out-of-range rolls, slot rule breaks or duplicate affixes
  • Mass projectile and AoE damage resolver written three ways: smart pointers, array of structures with generational handles, and structure of arrays
  • All three versions produce identical results, so the benchmarks measure memory layout alone

Cellular Automata for Roguelike Dungeons

Research project

I built a benchmark tool that generates dungeons with three methods across six grid sizes, from 20 × 20 up to 300 × 300, with 30 runs per size. A run counts as a complete level when the map is fully connected and has a player spawn and an exit.

Random fill never produced a complete level. Both cellular automata methods reached 100% from 200 × 200 up, and at 300 × 300 the hybrid's grammar pass cost about 0.2 ms per map.
